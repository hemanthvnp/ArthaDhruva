# model-validation MCP server

Checks on the committed model artifacts, never changes to them. The fourth server of
`openspec/changes/mcp-servers-and-analyst-agent` (task group 8). It does not export, retrain or regenerate anything.

## Tools

| Tool | Does |
|---|---|
| `verify_artifacts` | SHA-256 of each committed artifact against the checksum its model card records: `match`, `mismatch` (with both checksums) or `missing`. Any mismatch or missing file fails the whole result. The service enforces the same contract at start-up; this checks it from outside, without starting it. |
| `run_golden_test` | Runs `TermStructureGoldenTest` through the Maven wrapper (10-minute limit): the Java engine against the independent Python implementation, to 1e-6. `passed`, `failed` (with the relevant output) or `skipped` (never `passed`) when Maven cannot run here. |
| `rerun_advisory` | Compares the working tree with a base ref (default `HEAD`; a branch such as `origin/dev`) and, when a model artifact or its export script changed, says which golden script **the owner must re-run** and which Java test then checks it. |
| `drift_report` | The origination PD model's population-stability report, exactly as `GET /v1/models/pd_24m/drift` returns it, with its source and fetch time. |
| `survival_backtest` | The survival model's backtest, exactly as `GET /v1/models/survival/backtest` returns it. |

## Configuration (environment only)

| Variable | |
|---|---|
| `MODEL_VALIDATION_REPO` | Repository root; default the git root of the working directory. |
| `RISK_ENGINE_URL` | Backend base URL, default `http://localhost:8080`. |
| `RISK_ENGINE_SESSION` | `ad_session` cookie of a signed-in user. Only the two reports need it; without it they say it is not set. Secret. |

## What it will and will not run

The command line of the one process it starts is fixed in `src/golden.ts`; no tool takes a command. A request that names an
export (`export_*.py`), `fetch_macro.py`, a dataset build, a golden-fixture script (`golden_*.py`), a model-card script
(`validate_*.py`), the data pipeline, a notebook or compose profile is `Forbidden` before anything is spawned, and the message
says the **owner** must run it: those need the raw archives, take a long time, and change artifacts whose checksums the service
refuses to start without.

When a golden script is out of date, `rerun_advisory` says so and stops. A fixture regenerated by a tool that did not check why
it changed would hide the very drift the golden test exists to catch.

## Limits

- The checksum is over a file's bytes as they are on disk. It is meaningful for the binary ONNX files and for the JSON files
  pinned to LF in `.gitattributes`; a text artifact that Git converts to CRLF on checkout would mismatch its card. (That is how
  the regime-chain card broke Linux CI on 2026-11-04; the fix pinned its line endings.)
- `skipped` means the check did not happen. It is reported when Maven or Java is missing; a compile error, a timeout, or Maven
  finishing without a result for the test is a **failure**, not a skip.
- A run takes tens of seconds (42.9 s here) and writes build output under `backend/risk-engine/target/`. If an editor's Java
  language server holds that folder open, Maven can fail on file locks; the output is returned.
- The advisory's file lists are what each golden script reads today (`src/advisory.ts`). A new input to a script must be added
  there.

## Tests

`npm test` from `tools/mcp`: `test/model-validation.test.ts`, 23 tests, including the repository's own seven artifacts against
their cards, a real throwaway git repository for the advisory, and every forbidden request. The real golden test was also run once
through the real server (passed, 2 tests, 42.9 s); that run is not part of `npm test`, since it needs Java and Maven.
